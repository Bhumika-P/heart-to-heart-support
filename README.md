# Heart to Heart Hope and Healing

A responsive support-group website for Sherée Bergman, built from the documents and visual concept in `Z:\Mom Website`.

The site includes Home, About, Group Sessions, Resources, FAQ, Contact, a printable/downloadable confidentiality agreement, privacy and terms pages, and a private administration dashboard. It uses Firebase Authentication, Realtime Database, and callable Cloud Functions. It does not use Firestore.

## Local preview

Requires Node.js 22.

```powershell
npm ci
npm --prefix functions ci
npm run build
npm run preview
```

Open http://127.0.0.1:4173. The Firebase-backed features require deployed rules/functions and enabled authentication, or the emulators described below. Opening source HTML directly as a file is not supported; the build bundles the Firebase SDK.

## Organization

Root-level HTML pages and `assets/css`, `assets/js`, `assets/img`, and `assets/files` follow the organization of banrigaming.github.io. Shared page markup is generated by `scripts/create-pages.py`; full original body copy is retained in `docs/source-content.json`. Edit the page generator for shared markup, CSS for styling, and the JavaScript modules for behavior. Running the generator requires Python 3; normal builds do not.

`functions/` contains the validated backend and administrator provisioning utility. `docs/` contains requirements and design notes. `tests/` contains validation, content/link, and emulator integration tests. `dist/` is the generated deployable site; it excludes documents, source configuration for email, admin addresses, tests, and backend source.

## Firebase setup

Follow [firebase-setup-notes.md](firebase-setup-notes.md). The exact copy-and-paste database rules are in [firebase-realtime-database-rules.json](firebase-realtime-database-rules.json).

No live sessions are seeded. Administrators enter real dates, times, timezone, and locations. The concept's sample Tuesday/Thursday times are not assumed to be confirmed meetings.

## Verification

```powershell
npm test
npm run test:integration
```

Integration tests require Java 21+ for the Firebase emulators. They run only against the `demo-heart-to-heart` project on loopback, create disposable synthetic records, and never send real email. The tests reset that demo database; do not run them against an emulator holding data you want to keep.

For interactive emulator use:

```powershell
npx firebase emulators:start --project demo-heart-to-heart --only auth,database,functions
```

Open `http://127.0.0.1:4173/index.html?emulator=1`. This switch only works on loopback. Local emulator notifications are explicitly marked as simulated, so local success is not evidence of inbox delivery.

## Current delivery status

The implementation is local and has not been deployed or pushed. Live activation requires Firebase Email/Password sign-in, provisioning the addresses in the private `admins.txt`, the database rules, deployed functions, and SMTP configuration. The public website is never given SMTP credentials. See the setup notes for the ordered activation steps and verification checklist.
